# Tests/perf-suites.txt: the perf and timing tests, kept out of the merge gate.
# A test belongs here when it asserts a wall-clock or allocation budget, so a
# busy machine can fail it while the code is fine. scripts/ci (Linux and
# macOS, full and --changed) and CI's scoped runs skip exactly these; they
# run nightly on the captain's Mac (perf-nightly), one at a time
# (`scripts/test-scope perf [APP]` gives the filter), and never in CI.
# `scripts/test-scope perf-report` turns that run's log into a report and
# warns on a bound missed by more than 3x (FLAG in scripts/test-scope).
#
# One test per line: <app> <id>. app is the scope that measures it (flare,
# design, photo, library, halo, suite, suiteui). id is Target.Suite (every
# test in it), Target.Suite/test (one test, when the rest of the suite times
# nothing) or Target.freeTest. Tests/test_scope checks each id exists. Only
# the supervisor edits this file.
